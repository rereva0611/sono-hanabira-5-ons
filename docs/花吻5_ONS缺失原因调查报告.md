**调查对象**：《その花びらにくちづけを あなたを好きな幸せ》（SonoHana 5 / 花吻在上5 / 爱上你的幸福 / The Joy of Loving You），PC 版 2008-07-25 发售（VNDB v938）  
**调查日期**：2026-09-16  
**调查方式**：公开网络线索追踪（中文互联网 / 日文 / 英文 / GitHub / Internet Archive / VNDB API / 工具作者原始页面 / 工具源码）

## 1. Executive Summary

**历史上有没有 ONS5？**

没有发现任何"公开流传的完整 ONS5"的可靠证据。缺口是真实的，且在文件层面可验证：一个收录 189 个 ONS 游戏的大型中文归档（zi0.cc，索引时间戳 2023-04-26）在《ONS合集》下收录了花吻 **1、2、3、4、6、7、8、9、10、13、16 与番外『花瓣！』**，**独缺 5**。中文社区自 **2018-04-01** 起就有人在贴吧明确记录"花吻在上5 爱上你的幸福 没有 ons 版"，到 **2025-08-13** 仍有人发帖问"ons 第五部在哪"。**该缺口至少持续 8 年且至今未补。**

**为什么没有？**

**关键发现：第 5 作在技术上并不是异类，也不是死路。** 证据链一致指向"这是移植人力/生态问题，不是格式问题"：

- 引擎层面：FJSYS 归档格式（魔数 `FJSY`）对整个系列是**统一**的，2025 年的 `FJSYS-Extractor` 明确支持**第 1–12 作（含第 5 作）**。
- 工具层面：Proger 2009 年的 FJSYS 工具集在 changelog 中**点名支持「Anata wo Sukina Shiawase（好きな幸せ）」**。没有任何工具文档显示"第 5 作被单独排除"。
- 旁证层面：**第 5 作的 VNDS 移植确实存在且完整**（Internet Archive `vnds-retail-games`，2020-11-15 上传，含 `Sono Hanabira ni Kuchizuke Wo 05 - The Joy of Loving You.zip`，133.7 MB）；第 5 作的 Ren'Py 移植在中英文圈**都存在**。一个比 ONS 弱得多的引擎都能承载 5 的内容，说明"ONS 无法表现 5"不成立。

**最可能的原因**：ONS 移植本质上是**重写**而非格式转换（中文圈对"移植"的定义即"从零开始自己写程序"），因此产出量取决于个别移植者的精力与覆盖范围。2010 年代中期之后中文 ONS 移植生态急剧萎缩（2022 年一篇移植教程直言"移植在近 5 年内确实非常稀少"），目前唯一被识别出的花吻 ONS 移植者（贴吧 ID `254224193`，2015 年）做的是**第 16 作**，而不是第 5 作。**第 5 作是"被跳过"而不是"做不了"。**

**置信度**

| 结论                  | 置信度                                      |
| ------------------- | ---------------------------------------- |
| "缺 5"现象真实且持续 ≥8 年   | **高**（多条独立一手社区陈述 + 文件级归档证据）              |
| PC5 不是异类引擎、不是技术死路   | **高**（解包器支持 1–12；VNDS/Ren'Py 均有 5）       |
| 从未存在过公开流传的完整 ONS5   | **中高**（在已查到的所有索引中零痕迹；但私聊/QQ 分发无法证否）      |
| ONS 移植是"人工重写"而非自动转换 | **中**（由工具清单中不存在 FJSYS→ONS 转换器 + 移植者自述推断） |
| 根因是人力/生态而非格式        | **中**（最受支持，但**移植者身份未查明**，无法拿到移植者原话）      |

### 3.2 ONS 版 1–4、6–10、12、番外 的移植者：**未查明**

- 文件层面唯一的共同标记是 `[yurinyurin]` 前缀。经核实，`ゆりんゆりん / Yurin Yurin` 是ふぐり屋的**商業品牌名**（Weblio：「同人サークルであるふぐり屋、商業ブランドであるゆりんゆりん」），且该归档中其他条目同样以**原厂/发行商**为前缀（`[ALcot]`、`[AUGUST]`、`[5pb.]`、`[AKT]`…）。
- **因此 `[yurinyurin]` 不是移植者署名，而是归档整理者使用的厂商前缀。** （这一点是对早期推断的修正，避免误认。）
- 由此得出：**无法回答"1–4 是否同一人所做""4 和 6 是否同一人""为什么做完 4 跳到 6"**——因为根本找不到任何一份该 ONS 套件的移植者署名。
- 间接线索：`花吻1` 有两个近乎同尺寸的副本（`花吻1` / `花吻在上 1`），`花吻4` 有两个**不同尺寸**的版本（186,340,928 B 与 182,861,167 B）——这更像**重复转载/多版本打包**，而非多人移植。

1. **【已证实】** FJSYS 的格式解析层对 1–12 作统一，**没有"第 5 作专属格式"**。

### 6.2 "为什么某些版本要单独加支持"——机制解释

**已证实的机制有三类，都与"逐作变化"有关，且都不只针对第 5 作：**

1. **按作品的 MSD 加密密钥（最主要）**
   - GARbro 源码：遇到含 `.msd` 的归档就要求密码，密码按**游戏标题**查表（`KnownPasswords[title]`）。
   - Proger 的 changelog 明确记录"**修正花吻1 的 MSD 加密密钥**"，且 2021 年还"修复了十六进制密钥输入"。
   - → **每作（或每若干作）密钥不同**；移植者若拿不到某作密钥，就**无法解出该作剧本**。这是最可能导致"某作被跳过"的机制。
2. **字符集 / 心形符号（♥）**
   - 2010-11-01 为**花吻4**单独加心形符号支持；2011-03-21 又为"**第 3 作及之后**"加；2011-07-17 再修"连续心形符号"。
   - → 字符集在系列中期发生过变化，**但变化点在第 3–4 作，不在第 5 作**。
3. **文本换行 / 冒号截断**
   - 2011-03-21 的换行改进、2011-07-17 的冒号修复，均为"第 3 作及之后"。

**因此：工具史中所有"需要单独加支持"的记录，指向的是第 1 作（密钥）、第 3–4 作（字符集/换行）、第 9/10 作（MSG 归档）、第 10+ 作（新作品），而不是第 5 作。**

### 6.3 ⚠️ 未解决的关键歧义（必须点明）

Proger 2009-09-22 的原文是：

> `1 = Sono Hanabira ni Kuchiduke wo, 2 = …Watashi no Ouji-sama, 3 = …Anata wo Sukina Shiawase（好きな幸せ）`

按 VNDB 发售顺序，**第 3 作是「あなたと恋人つなぎ」，第 5 作才是「あなたを好きな幸せ」**。两种读法：

- **读法 A（很可能是笔误）**：`1/2/3` 是按发售顺序列游戏，作者把第 3 作的副标题写错（两作都以「あなた」开头，极易混淆）。若如此，这段 changelog 只说明"支持到第 3 作"，**与第 5 作无关**。
- **读法 B（若是正确的，即为关键线索）**：`msd_1 / msd_2 / msd_3` 代表 **FJSYS 的三代格式**，作者按"代表作品"列名，那么「あなたを好きな幸せ」就是**第三代 MSD 格式的首个使用者**——这会是一个真正的"第 5 作特殊性"证据。

## 8. "为什么没有 ONS5" 的候选解释（不评分）

### 候选 1：ONS5 曾存在但失传

- **支持证据**：U1（2020，"有个大佬给我的好像有5"）、U2（2025，有人答"有"并私发 QQ）。ONS 资源长期靠网盘/QQ 私传，公开索引天然不完整；ONS 套件本身也存在"同作多版本"现象（花吻1 两份、花吻4 两份且尺寸不同），说明套件有反复重打包的历史。
- **反对证据**：在本次查到的**所有**索引中零痕迹——包括一个 189 条的 ONS 合集、一个 6,948 路径的大归档、以及 8 年间所有相关贴吧讨论，**没有任何一次出现"花吻5 ONS"的文件名、截图或下载帖**。若曾公开发布，8 年间不可能一次都没被引用。
- **缺失证据**：任何 ONS5 文件、截图、发布帖、存档快照。QQ 私聊分发在技术上不可追溯，因此**无法完全排除**。

### 候选 2：PC5 存在特殊技术障碍

- **支持证据**：FJSYS 的 MSD 剧本**按作品独立加密**（C6）；工具作者曾**为花吻1 单独修正密钥**（C7）；字符集/心形符号曾在第 3–4 作附近发生变化（C7）。→ 说明"逐作差异"客观存在，原则上某作可能卡在密钥或字符集上。
- **反对证据（强）**：`FJSYS-Extractor` 明确支持**第 1–12 作含第 5 作**（C5）；格式解析器**无按作品分支**（C6）；Proger 工具集**点名支持 好きな幸せ**（C7）；**VNDS 5 完整存在**（C3）；**Ren'Py 5 中英双版存在**（C4）。→ "第 5 作是异类"被多重否证。
- **缺失证据**：PC4/PC5/PC6 的实际文件差分（归档头、MSD 头、命令集、字符集表、密钥）。**未做。**

### 候选 3：转换工具不支持 PC5

- **支持证据**：**无。** 未找到任何"排除第 5 作"的工具文档。
- **反对证据**：C5、C7 均显示工具支持第 5 作；GARbro 的 FJSYS 处理器**与作品无关**，只需密钥（C6）。**另需注意**：本次检索**没有发现任何 FJSYS→ONScripter 的转换器**——ONS 移植不是"转换"，而是"重写"（见 P1）。
- **缺失证据**：对 Proger `msd_1/2/3` 源码中**各版本密钥注释**的核对（解压失败，见 6.3）。

### 候选 4：ONS 无法表现某些 PC5 功能

- **支持证据**：ONS 是**重写**，必然有取舍——已确证的 花吻16 ONS 版**删除了 flag 判定**、**未实现系统菜单**（C11）。
- **反对证据**：ONS 同系列其余 10 作均能实现；PC5 的功能集合（文本+CG+立绘+BGM+语音+少量选项）与其邻居同构；**VNDS（远弱于 ONS）已完整承载第 5 作**（C3）。
- **缺失证据**：PC5 的功能/命令清单。**未做。**

### 候选 5：有人尝试但放弃

- **支持证据**：U3 的"第五部不是玩不了吗"这一说法，语义上更像"某人试过但没成"，而非"从来没人做"。
- **反对证据**：**没有任何开发日志、帖子、评论、README 或"坑了"的记录**。贴吧、ons安卓吧、ons汉化吧、ons吧的检索均无相关开坑帖。
- **缺失证据**：移植者的开坑/弃坑记录。

### 候选 6：社区/人员原因导致无人完成

- **支持证据**：
  1. 中文 ONS 移植在 2015 年后基本停摆（C11 是最后一位可考 ONS 移植者；C12 直言"近 5 年移植非常稀少"）。
  2. 现存 ONS 套件是 2010 年代产物，**逐作零散缺口**（第 5 缺、第 15"可能有问题"、第 11/17/19/20 也无）——符合"人力覆盖不全"的特征，而非"格式世代限制"。
  3. 当前移植人力**整体转向 Ren'Py**（C4），且现代移植者**明确表示搞不懂老引擎**（C10）。
  4. 老引擎工具链被描述为**残缺、部分不可用、不能封包、输出不可读**（C9、C8）——做 ONS 移植的**成本显著高于做 Ren'Py 移植**。
- **反对证据**：**无法解释"为什么做了 4 却跳过 5 而去做 6–10"**——若同一人顺序作业，跳过中间一作是反常的。这一点在没有移植者身份的情况下无法解释。
- **缺失证据**：ONS 套件移植者身份与其作业顺序的任何记录。

### 候选 7（补充，用户未列）：ONS5 从未被需要，因为第 5 作已有更省力的替代方案

- **支持证据**：第 5 作同时存在 VNDS 版（C3）、Ren'Py 英文版与中文汉化重置版（C4）；Fuguriya 官方亦通过萌えAPP / App Store 推出过部分作品的手机版（例如「出会った頃の思い出に」2015、「ミカエルの乙女たち」2017）。"能玩到"的路径不止 ONS 一条。
- **反对证据**：中文社区对 ONS 的需求明确且持续（2018、2020、2022、2023、2025 年均有索求），"没人需要"不成立。
- **缺失证据**：官方手机版是否覆盖第 5 作（**未核实**；已知的两例都不是第 5 作）。

## 10. 最终结论

### 【已证实事实】

1. **"缺 5"是真实的、文件级可验证的缺口**，且在中文社区被**至少 8 年（2018-04 → 2025-08）持续记录**。
2. 中文 ONS 套件覆盖 **1、2、3、4、6、7、8、9、10、13、16、番外『花瓣！』**，**不含第 5 作**；同套件也无 11、17、19、20 等作。
3. **第 5 作的 VNDS 移植存在且完整**（含 CG、语音、选择支脚本），Internet Archive 2020 年存档可查。
4. **第 5 作的 Ren'Py 移植中英双版均存在**；中文汉化重置覆盖 1–9。
5. **FJSYS 归档格式对第 1–12 作统一**（魔数 `FJSY`，解析器无按作品分支）；**2025 年的解包器明确支持第 1–12 作含第 5 作**。
6. **MSD 剧本归档按作品独立加密**，需要密钥；工具作者曾**为第 1 作单独修正密钥**，并在 2021 年仍补充新作支持。
7. **GARbro 无法重新封包 FJSYS 归档**；老引擎工具链被多方描述为残缺、部分失效、输出不可读。
8. **ONS 移植 ≠ 格式转换，而是人工重写脚本**（移植者自述 + 教程定义 + 工具清单中不存在 FJSYS→ONS 转换器）。
9. **唯一被识别的花吻 ONS 移植者（`254224193`，2015）做的是第 16 作**，且在移植中删除了 flag 分支判定。
10. 百度知道的"没有买到版权"解释**不成立**（ONS 移植无授权环节）。

### 【高可信推断】

1. **第 5 作不是"做不了"，而是"没人做"（或被跳过）。** 支持这一点的证据链最强：格式统一、工具支持、VNDS 完整、Ren'Py 双版。
2. **根因在于中文 ONS 移植生态的规模与寿命**：套件逐作零散缺失（5 缺、15 有问题、11/17/19/20 无），符合"人力覆盖不全"而非"格式世代限制"；2015 年后 ONS 线停摆，人力转向 Ren'Py。
3. **ONS 套件 1–4、6–10 的移植者身份已不可考**；`[yurinyurin]` 是原厂品牌前缀，**不是移植者署名**。
4. **"ONS5 曾公开存在但失传"的可能性低**——8 年间在所有可查索引中零痕迹。

### 【尚未证实】

1. **ONS5 是否曾私下存在**：仅有 2020、2025 两条无法验证的二手说法，且与 VNDS/Ren'Py/PC 版混淆的风险很高。
2. **PSP 版是否同样缺第 5 作**：PSP 版"共 8 款"，名单未取得。**这是判断"缺口是否在 ONS 上游"的关键分叉点。**
3. **Proger `msd_3` 的真实所指**：是笔误（第 3 作）还是格式世代（第 5 作）？未能读取其 readme 与源码。
4. **PC5 是否存在独有命令 / 独有字符集 / 独有密钥难度**：**未做文件差分，不做任何断言。**
5. **是否存在过失败的移植尝试**：无任何开坑/弃坑记录。


### 【下一步验证方法】（按性价比排序）

**实验 1（最高优先，成本低）：解决 Proger 的编号歧义**

- 用真正的 RAR 解压器（`unar` / WinRAR / `unar`+`lsar`）解开 `msd.rar` 与 `arctool.rar`，读 `readme.txt` 与 `src/msd_1|2|3.dpr`。
- 判定标准：若源码/readme 把某把密钥注释为「好きな幸せ」，则 **读法 B 成立**——第 5 作是 FJSYS 第三代格式的首个使用者，需要立刻转入实验 4 做定向差分。

**实验 2（高优先）：取回 PSP 版完整 8 款名单**

- 目标：百度知道 529829236 的回答正文；pspgal吧 花吻帖；花吻在上吧置顶（帖 7338237616 / 10864852930）。
- 判定标准：**若 PSP 8 款同样不含第 5 作 → 缺口在 ONS/PSP 的共同上游（指向 PC5 数据层面）；若含第 5 作 → 缺口是 ONS 生态独有，候选 6（人力/生态）成立度大幅上升。**

**实验 3（中优先）：确认 ONS 套件是否真的是"重写"**

- 取一份花吻 ONS 包（如第 1 作，约 119 MB），检查 `0.txt` / `nscript.dat` / `arc.nsa` / README，寻找：移植者署名、脚本注释、工具生成痕迹、`convert` 等字样。
- 判定标准：若脚本中出现与 MSD 结构对应的自动生成痕迹 → 存在未知的 FJSYS→ONS 转换器（P1 被推翻，需重估）；若为手写风格 → P1 成立。
- 附带目标：**拿到移植者 ID，然后回答"为什么做完 4 跳到 6"。**

**实验 4（需合法样本）：PC4 / PC5 / PC6 文件差分**

- 用 `FJSYS-Extractor` + GARbro 对三作做：
  1. 归档头对比（`FJSY` 魔数、`count@0x10`、`index@0x54`、条目布局是否一致）；
  2. MSD 条目是否以 `MSCENARIO FILE  ` 开头（即是否未加密）；
  3. **命令集统计**：解出 PC4/PC5/PC6 的 MSD 命令操作码，做三列对照表，找"PC5 独有命令"；
  4. 字符集表对比：心形符号（♥）编码位置在第 4/5/6 作是否一致；
  5. 若三作密钥均未知，则用 Proger `msd_1/2/3` 或 ArcTool 的密钥机制反推密钥差异。
- 判定标准：**只有在 PC5 上出现 PC4、PC6 都没有的命令或字符集差异时，候选 2（特殊技术障碍）才成立。**

**实验 5（补充）：Web Archive 定向回捞 2010–2015**

- 检索 `web.archive.org` 对 花吻在上吧 / ons安卓吧 / ons汉化吧 / 115网盘 / 迅雷快传 快照，关键词 `花吻 ons 移植`、`花吻 合集`、`补档`。
- 目标：找到 2010–2015 年的 ONS 套件**原始发布帖**（而非转载帖），这是唯一可能回答"1–4 与 6–10 是否同一人"的途径。
